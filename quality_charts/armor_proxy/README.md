# Armor proxy ヒートマップの見方

このディレクトリの図は **`tools/plot_melee_throwing_quality_comparison.py`** が生成します。ゲーム内の実DPSそのものではなく、**鎧を単純なスカラーで表したときの「火力の並び・相対感」**を読むためのレイヤー1用です。

---

## 共通の前提

### 鎧プロファイル（列の意味）

| profile | mitigation | 読み |
|---------|------------|------|
| none | 0.00 | 鎧なし |
| light | 0.28 | 軽装相当（遠隔チャートの `light` と同じスカラー） |
| plate_iron | 0.68 | 重装寄り（遠隔の `heavy` と同じスカラー。特定の鉄板アイテムではない） |

### HPに入るダメ（フラット鎧代理）

`mitigation > 0` のとき、概ね次のイメージです。

`dealt_hp = damage × (1 − mitigation × (1 − ignoresArmor))`

この式では **`armorDamage` はHPダメに乗りません**。斧・鈍器の「防具を削る」強さは **`armor_proxy_flat.csv`** の列や、**decay 付きシミュ**（後述）で補います。

### 期待DPS代理（セルの数値の意味）

`expected_dps_proxy ≈ dealt_hp / attackSpeed × precision`

- **距離**と **`precisionFalloff`** は入っていません。
- したがって図は **「同じ前提での武器・系統同士の比較」**向きで、立ち位置やフォールオフ込みの絶対評価には使いません。

### 品質・データセット

- **mod のみ**の単一ヒートマップ（`armor_proxy_heatmap_*.png`）は **品質 Q3・mod（Equipment + 品質表）** です。
- **vanilla と mod の比較**図は、同じく **Q3** で左右に分かれています。

---

## ヒートマップの活用の仕方（全体像）

これらの図は **「バランスの最終判定」ではなく、レイヤー1のスクリーニングと仮説出し」**向きです。次のように使うと安全です。

### 向いている用途

| やりたいこと | 主に使う図 |
|--------------|------------|
| 系統内で「鎧が重いと誰が相対的に死ぬか」をざっと見る | mod のみの **系統別**図（`armor_proxy_heatmap_{sword,…}.png` / `ranged`） |
| 同じ武器・同じ鎧代理で **mod が vanilla からどう動いたか** | `armor_proxy_heatmap_compare_*.png` |
| **武器種同士**で「この代理では誰が鎧列で強いか」の俯瞰 | `armor_proxy_heatmap_type_vs_armor.png` の **上段**（断定はしない） |
| **武器種ごとに**鎧の影響の「形」だけ比較したい | 同ファイルの **下段**（行の中だけ見る） |
| 品質や vanilla/mod の数値追跡 | 図ではなく **`armor_proxy_flat.csv`** |
| `armorDamage` や複数ヒット後の話 | **`armor_proxy_sim_Q3_n20.csv`**（decay 列）とプレイ確認 |

### おすすめの読み順（例）

1. **系統別 mod 図** … 明らかな外れ値・「重装列だけ異常に暗い／明るい」武器がないか。  
2. **compare 図** … 意図した調整がその武器・鎧条件で反映されているかのざっくり確認。  
3. **type_vs_armor** … 上段で系統間の並びの感覚、下段で「鎧ペナルティの形」が設計意図と矛盾していないか。  
4. 疑わしいところだけ **flat / sim** で数値確認 → 必要なら **ゲーム内**で検証。

### 向いていない用途（ここだけでは決めない）

- 実戦での強さの最終ランキング（距離・フォールオフ・AI・地形が無い）。  
- 「鎧割り特化」の評価（フラット系の式に `armorDamage` が乗らない）。  
- 「剣が強すぎる」等の一言断定（上段は系統内**中央値**でも、モデル外の要因は多い）。

## ファイル別の見方

### 1. `armor_proxy_heatmap_{sword,spear,axe,blunt}.png` と `armor_proxy_heatmap_ranged.png`

**mod・Q3**のみ。

- **行**: その系統に含まれる各武器（または投擲の throw / melee などのモード）。
- **列**: 上記の鎧3種。
- **色が明るいほど**、その条件での **期待DPS代理が高い**（**その図の中での相対**）。

**読み方の例**

- **同じ列で行を比べる** → 同じ鎧前提での系内ランキング。
- **同じ行で列を比べる** → その武器が鎧を重くしたときにどれだけ落ちるか（左から右へだいたい暗くなるのが普通）。
- **右列（plate）でも明るい** → 重装代理でも相対的に保てる（無視率・速度・精度の合成結果）。

遠隔図は弓・クロスボウ **7本**が行になり、列の意味は近接と同じです。

---

### 2. `armor_proxy_heatmap_compare_{sword,spear,axe,blunt}.png` と `armor_proxy_heatmap_compare_ranged.png`

**左パネル = vanilla（本体＋vanilla品質表）、右パネル = mod（mod装備＋mod品質表）**。行・列は上記の mod のみ図と同じです。

- **左右で色スケール（vmin/vmax）が共通**なので、同じ明るさは同じ数値スケール上の位置として読めます。
- **同じ行・同じ列を左右で見る** → その武器・その鎧代理での **vanilla と mod の差**。

---

### 3. `armor_proxy_heatmap_type_vs_armor.png`（武器系統 × 鎧）

**武器系統5行**（剣系・槍＋投槍・斧＋投斧・鈍器・弓弩）× **鎧3列**。Q3・mod。  
上段の各セルは、その鎧列について **系統内の全モード（弓は7本）の期待DPS代理の中央値**（平均より両手・高火力モードの押し上げを受けにくい）。

**上段と下段の役割の違い**

- **上段** … **武器種同士**を、同じ鎧条件で比べる（どの系統が強いか）。  
- **下段** … **武器種同士の比較ではない**。**武器種ごとに**、鎧を重くしたときに期待DPS代理が「その系統の行のピーク」からどれだけ残るか（＝**鎧の影響をどれだけ受けるか**）だけを見る。比較するのは **常に同じ行の左→右**。

- **上段（絶対値）**  
  各行は、その系統に属する **全モード（または弓7本）の期待DPS代理を、鎧列ごとに中央値**で集約したもの。  
  - **縦に比べる** → 同じ鎧列での **系統間の強さ**の目安。  
  - **横に比べる** → その系統が鎧を重くしたときの落ち方（絶対値での傾き）。  
  - 以前は**平均**だったが、`greatsword` / `longsword` などが **剣系の行を明るく押し上げる**ことがあったため **中央値**に変更した（「典型の1本」に近い読み）。

- **下段（magma、0〜1）— 何をしているか**  
  **鎧の影響の受け方**を、系統ごとに形だけ抜き出したもの。上段の **同じ行**について、3つの鎧列のうち **いちばん大きい数を 1** とみなし、他の2列をそれで割っています。

  `下段のセル = 上段のそのセル ÷（その行の3列の最大値）`

  だから **必ずその行のどこか1列がちょうど 1** になります（多くの場合は **鎧なし（none）が最大**なので左列が 1 に近い）。

  **具体例（イメージ）**  
  ある系統の上段の3値が `none=5.0, light=3.0, plate=1.5` だとします。行の最大は 5.0 なので下段は  
  `5.0/5.0=1.0`, `3.0/5.0=0.6`, `1.5/5.0=0.3`  
  となります。**plate の 0.3** は「重装代理のとき、その系統の“一番出るとき”に比べて **3割の強さに落ちる**」という意味です（上段が中央値でも、下段の割り算の意味は同じ）。

  **読み方**  
  - **同じ行の左→右**だけ見るのが主用途です。鎧が重くなるにつれ、下段の数が **どれだけ早く 0 に近づくか** が、その系統の **鎧に対するペナルティの形**です。  
  - **上段で明るい行**は「そもそも火力が高い」ことが混ざります。**下段は行ごとにスケールを潰す**ので、「強い／弱い」ではなく **「鎧でどれだけ相対的に死ぬか」**だけが残ります。

  **やってはいけない読み**  
  - **別の行のセル同士**を「下段だから同じ土俵」と比較しないでください。各行は **自分の行の最大で割り直しているだけ**で、行と行の間では「1」の意味する絶対火力は揃っていません。行をまたいだ比較は **上段**で行ってください。

## CSVとの役割分担

| ファイル | 役割 |
|----------|------|
| `armor_proxy_flat.csv` | 遠隔＋全近接モード × **Q1–Q6** × vanilla/mod × 鎧3種。数値の根と、品質・データセットの差の追跡用。 |
| `armor_proxy_sim_Q3_n20.csv` | **Q3固定**のキュレート武器について、**20ヒット**の合計と **static（軽減一定）** / **decay（仮想鎧HPが減る）** の比較。`armorDamage` が長期戦で効くかの目安。 |

ヒートマップは主に **一覧と直感**、細かい数値や品質スイープは **flat**、鎧耐久の簡易効果は **sim** を参照してください。

---

## 上段と下段のどちらが「評価しやすい」か

**用途によって逆**になります。

- **下段**は問いを1つに絞っている（**その武器種の行の中だけ**で、鎧が重いほどピークからどれだけ落ちるか）。前提が狭いぶん、**読み取りは単純**です。
- **上段**は **武器種同士の絶対比較**が載る一方、射程・`precisionFalloff`・`armorDamage` 由来の長期戦・ゲーム内挙動などが入らないので、**「強い／弱い」の断定は一歩重い**ことが多いです。だから「評価に使うのが難しい」と感じるのは自然です。

---

## 「鎧削りで実質防具無視率が上がる」と等価に計算できるか

**完全に「無理」とは言いません**が、このツールの式の立て方では **「等価 ignoresArmor」に押し込んで一行で表す**ことは **おすすめしません**（一意でない／誤解しやすい）。

- 被ダメはざっくり `damage × (1 − mitigation × (1 − ignoresArmor))` 型です。**鎧削り**は本リポジトリでは **`armorDamage` で仮想鎧HPが減り、ヒットごとの mitigation を下げる**（`armor_proxy_sim` の **decay**）として表現しています。
- **mitigation を下げる**ことと **ignoresArmor を上げる**ことは、1発だけなら被ダメに似た動きを起こし得ますが、**複数ヒット**では時間の経ち方が違い、列全体を「等価 ignoresArmor」に **一意に還元**するのは一般に **できないか、無理に数字を出すと嘘が混ざる**側です。
- 鎧削り込みの読みを足したい場合は、等価パラメータを無理に定義せず、**decay 前提の指標**（`armor_proxy_sim_Q3_n20.csv` の `expected_dps_proxy_decay` など）を **フラット列と並列**で見るほうが安全です。将来ヒートマップに載せるならも、**第三の列群／別パネルで decay** と並べる形が正直です。

## 注意（誤読しやすい点）

1. **期待DPS代理に距離・precisionFalloff が無い** → 遠隔・近接の実戦配置は反映されません。  
2. **フラット鎧の式に armorDamage が入らない** → 「防具割り主体」の読みは sim の decay 列や flat の `armorDamage` 列と併用してください。  
3. **鎧3種はゲーム内の装備一覧ではない** → バランス読み用のスカラーです。  
4. **上段で特定の武器種の行だけがどの鎧列でも明るい（黄寄り）** → この図の指標である **期待DPS代理の、系内中央値**ではその系統が高い、という意味です（両手が平均を押し上げる効果は中央値で弱めているが、**射程・`precisionFalloff`・近接カバー・`armorDamage` 経由の鎧削りなどは依然入っていない**）。それだけで「ゲーム内でその系統が強すぎる」とは言えません。懸念がある場合はプレイ検証や `armor_proxy_sim` / 他チャートと併用してください。  
5. **再生成** … リポジトリルートで  
   `python tools/plot_melee_throwing_quality_comparison.py`  
   を実行すると本ディレクトリの図と `../melee_throwing/layer1_eval_bundle.md` が更新されます。
