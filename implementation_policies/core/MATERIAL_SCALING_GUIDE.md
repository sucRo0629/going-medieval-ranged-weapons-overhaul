# バニラで素材倍率がない装備を倍率対応させる手順

バニラの Going Medieval では、一部の装備（弓など）は素材の選択肢がなく、素材によるステータス倍率（`damageMultiplier` など）が適用されないようになっています。
本ガイドでは、これらを金属インゴットなどの素材選択に対応させ、素材ごとの倍率を適用するための修正手順を解説します。

## 修正の目的
- 製作時に鉄や鋼などの素材を選択できるようにする。
- `MaterialSettings.json`（バニラ）で定義されている素材ごとの倍率（例: 鋼のダメージ 1.2倍）を装備に適用させる。
- バニラの近接武器と同様の「単一アイテム ID + 素材倍率」の管理方式に統一する。

## 手順 1: Production.json の修正

製作レシピを定義する `Data/Resources/Production.json` を修正します。

### 1.1. レシピの材料（recipe）の変更
特定の素材（例: `wood`）のみだったレシピに、素材カテゴリのビットマスクを追加します。
金属インゴット類を許可する場合は **`2048`** を使用します。

```json
"recipe": [
  { "key": "wood", "value": 50 },
  { "key": 2048, "value": 5 } // 金属インゴット 5個を要求（鉄・鋼などを選択可能に）
]
```

### 1.2. 完成品（produced）の指定
完成品は、素材ごとの ID（`iron_long_bow` など）ではなく、ベースとなる単一の ID を指定します。

```json
"produced": [
  { "blueprintID": "long_bow", "amount": 1 }
]
```

### 1.3. 分岐（customProducts）の削除
もし `customProducts` を使って素材ごとに完成品を出し分けていた場合は、そのブロックを **削除** します。
バニラの倍率システムでは、`produced` で指定されたベース ID に対して、使用された素材の倍率が自動的に適用されます。

## 手順 2: Equipment.json の修正

装備の性能を定義する `Data/Models/Equipment.json` を修正します。

### 2.1. ベースステータスの設定
`damage` などのステータスには、**倍率が 1.0倍の素材（通常は「鉄 / iron_ingot」）を使用した場合の数値** を設定してください。

- **例**: 鋼（1.2倍）でダメージ 30 にしたい場合、ベースには `30 / 1.2 = 25` を設定します。
- これにより、鉄で作れば 25 (x1.0)、鋼で作れば 30 (x1.2) のダメージになります。

### 2.2. 不要なバリアント ID の削除
`iron_long_bow` や `steel_long_bow` などの個別 ID 定義が残っている場合は、それらを削除し、ベース ID（`long_bow`）に集約します。

## 手順 3: その他関連ファイルのクリーンアップ

以下のファイルに個別 ID が登録されている場合は、ベース ID に置き換えるか、不要な行を削除してください。
- `Data/Constructables/ProductionComponentsRepository.json` (作業台の製作リスト)
- `Data/Research/Research.json` (研究の解錠項目)

## 仕組みのまとめ
Going Medieval のエンジンは、`Production.json` のレシピにカテゴリマスク（`2048` など）が含まれている場合、製作完了時に「どの素材が使われたか」を記録します。
そして、その素材の `MaterialSettings.json` にある `damageMultiplier` 等を、`Equipment.json` の基礎値に乗算して最終的な性能を決定します。

この方式により、アイテム ID を増やすことなく、素材による性能差を表現することが可能になります。
